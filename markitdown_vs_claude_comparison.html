# 検証観点 markitdown Claude 差分の要因
1 工程名の抽出 △ ◎ テキスト抽出時に文字間スペースが挿入され工程名が崩壊
2 担当レーンの認識 △ ◎ レーン名が文字バラバラで工程との紐づけが曖昧
3 フローの接続関係 ✗ ◎ 矢印は図形（Shape）のためテキスト抽出では取得不可
4 注釈・補足情報 △ ◎ テキストは取得できるがどの工程に紐づく注釈か判別不可
5 使用システム △ ◎ システム名は断片として散在し工程との対応づけが不可

🔧 markitdown が向いているケース

  • テキスト主体のドキュメント（.docx / .md / .txt）の大量変換
  • テキストレイヤー付きPDFからの高速抽出
  • CI/CDパイプラインへの組み込み（ローカル・高速・無料）
  • 100ファイル超のバッチ処理
  • コストを最小限に抑えたい初期段階の前処理

🧠 Claude 読み取りが向いているケース

  • pptx / PDF業務フロー図（図形・矢印・レーン配置を含む）
  • スキャンPDF・手書き文書のOCR的な読み取り

  • 読み取り結果をJSON / Mermaid等に直接構造化したい場合
  • 画像内の注釈・ラベルの認識が必要な場合

💡 業務フロー図での検証の結果

pptx×1 + PDF×3 の業務フロー図で検証した結果、5観点すべてでClaudeが優位。Claude ネイティブ読み取りを採用。 markitdownでは図形・矢印情報の消失やテキスト分断により、工程名・レーン・接続関係・注釈の正確な抽出が困難。 一方、テキスト主体の補助ドキュメント（議事録・仕様書等）が大量にある場合は、markitdownによる前処理 → Claudeで構造化、というハイブリッド運用も有効。
